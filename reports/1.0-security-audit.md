## 2. Dedicated adversarial `handle()` campaign (spec §10, §11, §13)

`harnesses/adversarial-authz.mjs` — **47 hostile requests** against the reference authority
boundary across the demo `order-server` (direct / admin‑only actions, query, snapshot,
server‑only state) and `device-monitor` (operator‑only + **system‑only** actions, event
ingress). Battery: anonymous · empty‑object principal · missing role · role wrong type
(number / array / object) · `null` / `''` / unknown role · `__proto__` pollution attempt ·
id‑only · principal carrying planted secret fields · deeply‑nested secret · malformed
credentials (`null`, `''`, 1 MB string, `{"role":"admin"}`, path traversal, newline
injection, SQL, planted bearer) · forged `axiom_principal` in `arguments` · wrong protocol
version · unknown / wrong‑kind ids · malformed `sinceRevision`.

Every request produced a **structured refusal**, never a mutation, never a native throw:

| surface | outcome |
| --- | --- |
| admin‑only action, 13 hostile principals + 10 malformed credentials | `AUTHORIZATION_DENIED` ×23; stock/orders unchanged |
| forged principal in `arguments` | `ARGUMENT_TYPE_MISMATCH` (the principal is authority‑computed, never client‑supplied) |
| wrong protocol version | `MALFORMED_REQUEST` |
| unknown / state‑id as action id | `UNKNOWN_SERVER_ACTION` |
| **system‑only** actions invoked by a client (anonymous **and** operator) | `INVOCATION_SOURCE_NOT_ALLOWED` ×6 |
| operator‑only reboot, anonymous / viewer | `AUTHORIZATION_DENIED` |
| unknown / oversized‑forged / null / string event payloads | `EVENT_PAYLOAD_INVALID` ×4, **zero side effects** |
| client `snapshot` | `STATE_AUDIT` (server‑only) **absent** from the client snapshot |
| malformed `snapshot.sinceRevision` (−1, 1.5, `"x"`, > MAX_SAFE, `{}`, `null`) | `MALFORMED_REQUEST` ×6 |

`unauthorizedSuccesses = 0 · unauthorizedMutations = 0 · failOpen = 0 · nativeThrows = 0 ·
secretLeaks = 0 · brokenForbiddenInvariants = 0`. Raw: `out/adversarial-authz.json`.

## 4. Cursor security (spec §12)

`harnesses/cursor-security.mjs` — a tenant‑isolated cursor‑paginated query. Principal `a1`
opens page 1 (its own rows) and receives a sealed `nextCursor`. Then:

| attack | result |
| --- | --- |
| replay `a1`'s cursor as principal `a2` | **refused** — no rows, none of `a1`'s rows disclosed |
| replay `a1`'s cursor as `admin` (broader scope) | **refused** — the cursor is bound to the issuing principal; no privilege pivot |
| byte‑mutated cursor | **refused** |
| cursor from a server with secret `S` used against a server with secret `S'` | **refused** (HMAC‑SHA256 seal) |
| `a1`'s own legitimate continuation | succeeds, stays in `a1`'s policy scope, advances monotonically |

**cursor‑as‑bearer leaks = 0.** The cursor is a sealed, principal‑bound continuation token,
not a bearer credential. Raw: `out/cursor-security.json`. Corroborated by
`subscription-cursor.test.ts` (fencing, foreign‑lease block, backward‑move rejection,
reconnect‑through‑different‑authority) and `query-runtime.test.ts` (`a tampered cursor is
rejected`) at elevated counts.

## 5. Secret leakage audit (spec §13)

The §2 harness planted a sentinel secret in principal records, credentials, event payloads
**and** the server's own `cursorSecret`, then scanned every `handle()` response JSON —
**0 occurrences**. CLI `--json` outputs (`validate` / `analyze` / `explain`) carry no host
paths or secrets (one benign exception: a deliberate `MODEL_LOAD_FAILED` echoes the
user‑supplied file path resolved to absolute — finding **CLI‑1**, LOW/INFO, not a secret).
Durable workflow / effect records store a principal **fingerprint**, not the credential
(design + `authorization-adversarial` with garbage credentials, green). **credential /
secret leaks = 0.**
