# Axiom 1.0 — API Stability (per‑symbol audit)

*Maintainer artifact. Not shipped.* Candidate: `1.0.0-rc.1`. Machine artifact:
`reports/1.0-api-symbol-classification.json` (every exported symbol of every published
package, classified).

## Statement

Axiom 1.0 commits to the `1.x` policy in `docs/COMPATIBILITY.md` (NORMATIVE): portable
semantic meaning is the frozen 0.17 contract; the public API surface is additive in minors,
never removed / incompatibly changed without a major; diagnostics are stable by class; the
CLI `--json` surface is the automation contract.

## Method

For each published package the exported‑symbol closure of `dist/index.d.ts` was walked with
the TypeScript compiler API and each symbol classified:

| class | rule |
| --- | --- |
| `STABLE` | named in prose docs (`docs/`, `README`, `AGENT_REFERENCE`, routing files) |
| `ADVANCED_STABLE` | implementer surface (provider / host / conformance / coordination / fingerprint / Server‑IR‑problem naming), **or** a contract‑vocabulary `type` / `interface` / `enum` / SCREAMING_CONST reachable from `index.d.ts` (the `.d.ts` is a normative API layer per `CLAUDE.md`), **or** a recognised entrypoint‑shaped function, not referenced by name in prose |
| `DEPRECATED` | `@deprecated` JSDoc, or a known superseded positional form (`preconditions` / `failureModes`) |
| `INTENTIONALLY_EXPERIMENTAL` | `@experimental` / `@alpha` JSDoc |
| `ACCIDENTALLY_EXPORTED` | undocumented, no contract or implementer signal — overwhelmingly lowercase internal helper functions leaked through `export *` |

## Accidental exports — disposition (spec §4)

**No `@internal` annotation exists anywhere in the source**, and every package barrel uses
wholesale `export *`. The residual `ACCIDENTALLY_EXPORTED` bucket (~228 symbols) is
therefore not a set of individually leaked names but a **structural property**: the package
surface is "everything any internal module exports." The bucket is overwhelmingly
undocumented lowercase helper / predicate / accessor functions — `canonicalJSON`,
`isEmpty`, `nonEmpty`, `deepFreeze`, `cloneValue`, `randomHex`, `subscriptionQueueLimit`,
`workflowStepById`, `translateExpression`, `sealCursor`, `randomCursorSecret`, … —
reachable from the package root but named in no contract.

**Adjudication: accept the current surface as public under the 1.x additive guarantee**
(finding **API‑1**), because:

- It is **additive‑safe**: nothing here can be *removed* without a major, but the 1.x
  policy already carves out "accidental internal exports … may be withdrawn in a minor once
  identified" (`docs/COMPATIBILITY.md`), so a later curation pass is not blocked.
- **No security exposure.** The cursor‑seal helpers (`sealCursor` / `sealLiveCursor` /
  `randomCursorSecret` / `cursorMatchesContext`) all require the authority's `cursorSecret`;
  exporting them does not weaken cursor binding (`reports/1.0-security-audit.md`
  §Cursor security: `cursor‑as‑bearer leaks = 0`).
- Not a §5 deep‑import problem (symbols are at the package root) and not a §43 "broken
  documented public API".

**Recommended (1.0.x, non‑blocking):** an `@internal` pass + an API‑extractor snapshot test
over `dist/index.d.ts` so the barrel is governed and the helper surface can be narrowed on
a minor.
