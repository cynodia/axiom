## MEDIUM

### XRT‑1 — independent Python runtime diverges from the frozen conversion grammar · `R2` · MEDIUM

- **What:** `axiom_indep` fails 2 base‑axis conformance fixtures the **reference
  `1.0.0-rc.1` runtime passes**: `conversion-number-to-text` (`1e-7` → `"1e-07"` instead of
  the contract's `"1e-7"`) and `conversion-text-to-number` (`"1_000"` → `1000` instead of
  the contract's `NaN`).
- **Whose defect:** the independent runtime's. `docs/EXPRESSIONS.md#conversions` (shipped in
  the `@cynodia/axiom` tarball) is exact — it lists `1e-7 → "1e-7"` and `"1_000" → NaN`
  verbatim. Reference rc.1 is contract‑correct; 46/46 root conformance passes.
- **Root cause:** Python‑idiomatic formatting in `axiom_indep` (`repr(1e-7) == '1e-07'`;
  `float("1_000")` accepts `_`).
- **Provenance:** pre‑existing. These fixtures were added by the 0.17 pre‑freeze correction;
  the pre‑freeze verification used *reconstructed* fixtures that deliberately omitted these
  host‑specific edges, and flagged the independent side `PENDING — to be run by the
  independent Python runtime maintainer`. rc.1's behaviour equals 0.17‑frozen — **not a 1.0
  regression**.
- **Impact on the release:** `semanticContractChanged == false` and the 1.0 **artifacts**
  implement the contract correctly. Strict spec §28 `R2 = 0` is not met; adjudicated as an
  independent‑runtime defect that does not impugn the 1.0 artifacts or the frozen contract.
- **Disposition:** non‑blocking for the artifact release; **qualifies** the "clean four‑way
  MATCH" claim. Fix belongs to the independent‑runtime maintainer (`axiom_indep` conversion
  grammar); **no rc.2** is implicated. Full detail: `reports/1.0-independent-runtime-regression.md`.

### API‑1 — uncurated public export surface · `API` · MEDIUM

- **What:** every package barrel uses wholesale `export *` and there is **no `@internal`
  annotation anywhere**, so ~228 undocumented internal helper functions
  (`canonicalJSON`, `isEmpty`, `deepFreeze`, `randomHex`, `sealCursor`,
  `randomCursorSecret`, `translateExpression`, `workflowStepById`, …) are reachable from
  package roots. No API‑surface snapshot test governs the barrels.
- **Impact:** additive‑safe under the 1.x policy (which already reserves the right to
  withdraw "accidental internal exports … in a minor once identified"). Not a deep‑import
  problem (§5 — all at the package root), not a broken documented API (§43). **No security
  exposure** — the cursor‑seal helpers all require the authority's `cursorSecret`
  (`cursor‑as‑bearer leaks = 0`).
- **Disposition:** adjudicated **accepted as public** for 1.0. Recommended for 1.0.x: an
  `@internal` pass + API‑extractor snapshot test. Non‑blocking. Detail:
  `reports/1.0-api-stability.md`.

### PKG‑1 — `engines` was undeclared · `PKG` · MEDIUM · **RESOLVED (RC‑prep pass)**

`"engines": {"node": ">=22.0.0"}` added to all 8 published manifests. Verified present in
every packed tarball. No semantic change.

## LOW (all non‑blocking)

### TOT‑1 — `handle(snapshot)` not total over a hostile `sinceRevision` · `SEC/OPS` · LOW

`server.handle({kind:'snapshot', sinceRevision})` throws a native `TypeError` (not
`MALFORMED_REQUEST`) when `sinceRevision` is a null‑prototype object, an array containing
one, or an object with a throwing `toString`/`[Symbol.toPrimitive]` — a diagnostic string
coercion runs before the integer check. **Not reachable over any JSON transport** (verified:
`serveOverHttp` returns `MALFORMED_REQUEST` for `{}` and `[{},{}]`). Read‑only, fail‑closed.
27/2800 fuzz cases. Fix: `typeof`/`Number.isInteger` guard before coercion. Detail:
`reports/1.0-totality-fuzz.md`.

### PERF‑1 — in‑memory persistence log grows linearly · `PERF` · LOW/INFO

`createMemoryPersistence` per‑commit latency rises ~linearly with the un‑compacted revision
count in one long‑lived process (~4.7× over 16 000 commits; heap flat; **not** O(n²)).
Dev/test adapter; durable adapters unaffected. Recommend a note in `docs/STORAGE.md`.
Detail: `reports/1.0-performance-baseline.md`.

### CLI‑1 — `MODEL_LOAD_FAILED` echoes an absolute path · `D1` · LOW/INFO

The `--json` `MODEL_LOAD_FAILED` message includes the user‑supplied model file resolved to
an absolute path plus the CLI's own install path (Node resolver text). Not a secret; the
path is the caller's own. Recommend trimming to the relative path.
