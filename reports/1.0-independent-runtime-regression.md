## Finding XRT‑1 — independent‑runtime conversion‑grammar divergence (R2 · MEDIUM)

Two base‑axis fixtures diverge. In both, the **reference `1.0.0-rc.1` runtime matches the
frozen contract**; `axiom_indep` does not:

| fixture | frozen contract (`docs/EXPRESSIONS.md#conversions`, shipped) | reference rc.1 | `axiom_indep` |
| --- | --- | --- | --- |
| `conversion-number-to-text` | *"`1e-7` → `"1e-7"`"* (exponent digits, **no leading zero**, §77‑78) | `"1e-7"` ✓ | `"1e-07"` ✗ |
| `conversion-text-to-number` | *`"1_000"` → `NaN`* (digit separators not in the portable numeric grammar, §121) | `NaN` ✓ | `1000` ✗ |

**Root cause:** Python‑idiomatic formatting in `axiom_indep` — `repr(1e-7) == '1e-07'`, and
`float("1_000")` accepts underscores (Python 3.6+). Both are `axiom_indep` bugs against a
contract that is exact and shipped in the `@cynodia/axiom` tarball.

**Classification:** `R2` (independent‑runtime defect). **Not** `R1` (reference is correct),
**not** `S1`/`S2` (the contract has an explicit table with these exact examples).

**Provenance:** these fixtures were added by the 0.17 *pre‑freeze contract correction*
(commit before `ea173f5`). The pre‑freeze verification recorded them "PASS / PASS / MATCH"
using *reconstructed* fixtures that **deliberately omitted host‑specific edges**
("scientific‑notation edge output … deliberately not asserted"). The **shipped** fixtures
assert those edges, so `axiom_indep` was never actually run against these two assertions
until this campaign. The 0.17 freeze summary itself flagged the independent side as
`PENDING — to be run by the independent Python runtime maintainer`. **rc.1's behaviour here
is identical to 0.17‑frozen** — this is not a regression introduced by 1.0.

## Adjudication (spec §28)

Strictly, `R2 = 0` is **not met** (2 R2). However:

- The divergence is entirely on the **independent runtime**'s side. The `1.0.0-rc.1`
  release artifacts implement the frozen contract correctly (46/46 root conformance;
  `docs/EXPRESSIONS.md` is exact and shipped).
- `semanticContractChanged == false`; `portableMeaning(rc.1) == portableMeaning(0.17
  frozen)` holds.
- Recommended resolution: the **independent‑runtime maintainer** aligns `axiom_indep`'s
  number→text exponent formatting and text→number digit‑separator handling with
  `docs/EXPRESSIONS.md#conversions`, then re‑runs the differential. **No reference change is
  implicated** — this does not produce an `rc.2`.

**Verdict for this gate (at first run):** `R1 = 0`, `S1 = 0`, `S2 = 0`. `R2 = 2` (XRT‑1),
adjudicated as an independent‑runtime defect that does not impugn the 1.0 artifacts or the
frozen contract, and does not block the artifact release — but the "clean four‑way MATCH"
claim is **qualified** until `axiom_indep` is fixed. NativeOperation boundary (§30)
reconfirmed nonportable and correctly refused by the independent runtime.

## XRT‑1 CLOSED — `axiom_indep` fixed (independent‑runtime‑only)

`axiom_indep/values.py` was corrected in the independent‑runtime workspace
(`axiom-tests/test17/independent-runtime/`), **no reference change, no contract change, no
fixture change**:

- `_js_number_to_string()` now applies the ECMAScript `Number::toString` radix‑10 case
  analysis (fixed for `1e-6 ≤ |x| < 1e21` and `0`; exponential otherwise, no leading zero
  in the exponent) instead of returning Python `repr()` — `1e-7 → "1e-7"`, `1e-6 →
  "0.000001"`, `1e20 →` fixed, `1e21 → "1e+21"`.
- `to_number()` matches the trimmed string against the canonical‑decimal grammar
  (`_CANONICAL_DECIMAL`) **before** `float()` — `"1_000" → NaN`, plus `"1,000"`, `"inf"`,
  `"infinity"`, `"nan"`, `"1e"`, `"5%"` → `NaN`. Radix‑prefixed and exact‑case `Infinity`
  forms unchanged.
- New regression guard `conversion_regression.py` (61 assertions) pins the whole class.
