# Axiom 1.0 — Provider Hardening

*Maintainer artifact. Not shipped.* Version `1.0.0-rc.1`. **Status: partial existing coverage; failure-injection campaign required before `1.0.0`.**

## Scope (spec §27-40, §66-67)

- Per public provider interface (`DataProvider`, `PersistenceAdapter`, integration /
  subscription / blob adapters, `CoordinationProvider`, `WorkflowStore`, migration stores):
  document required methods, transaction assumptions, error behavior, retry / idempotency
  assumptions, mutation observation, revision interaction, concurrency and durability
  expectations, and unsupported-capability behavior.
- Capability honesty: `supported` / `unsupported` / `partial`; partial support must state
  its limitation; a provider MUST NOT claim a semantic it approximates wrongly.
- Failure injection around: begin, read, write, commit, rollback, effect dispatch, event
  ingestion, subscription cursor persistence, blob finalization, migration checkpoint,
  coordination lease / fence — verifying defined semantic outcomes hold.
- SIGKILL / SIGSTOP campaign (spec §66): kill before/after commit, before/after effect
  dispatch, during workflow transition, during migration, during lease ownership, during
  cursor advancement. Recovery semantics validated.
- Concurrency campaign (spec §67): two actions; two authorities; workflow reclaim; scheduler
  firing; event dedup; migration startup; live-query mutation; subscription advancement.
  Required: `no corruption`, `no duplicate logical work`, `no stale fenced commit`.
